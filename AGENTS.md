# Development instructions

- Work on one approved task at a time in the `feat/react-ui` worktree. Check the branch and Git status before editing. Preserve all local changes and user files.
- For explicitly approved implementation tasks, create a local Git commit after successful verification. Before committing, inspect `git status` and the complete staged diff. Stage only files directly related to the current task. Never stage secrets, `.env` files, generated build artifacts, dependency folders, or unrelated user changes. Run relevant tests and checks before committing. If tests fail or unexpected changes are present, do not commit. Report the issue and wait for approval. Use a descriptive Conventional Commit message. Report the commit hash and committed file list. Never push, merge, rebase, reset, clean, or force-push without explicit permission. Do not automatically begin the next task.
- Use React + Vite, Python FastAPI, Gemini for parsing, Pydantic for data contracts, and Google OR-Tools CP-SAT for scheduling. See [the architecture documentation](.agent/rules/architecture.md) for the current architecture and approved roadmap.
- Keep the Python models, parser, validator, solver, API contracts, and frontend types aligned. Preserve existing Vietnamese code comments and existing API behavior unless the task explicitly changes it.
- Validate data structure and business rules before optimization. Use CP-SAT for scheduling and feasibility. Treat Gemini output as a draft users can review.
- From the worktree root, use `uv sync --locked` and run `uv run --locked python validator.py` and `uv run --locked python solver.py` when relevant. From `frontend/`, use `npm ci` and `npm run build`. Use presets for smoke tests without consuming Gemini quota. Keep keys out of Git and logs.
